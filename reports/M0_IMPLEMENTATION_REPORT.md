## 1) الملخص التنفيذي — الإجابة المباشرة على السؤال الجوهري

**هل أصبح لدينا مشروع Unreal حقيقي قابل للتشغيل؟ لا — وليس بعد.**

السبب مثبت بالفحص لا بالافتراض: هذه البيئة (حاوية Debian 13 بلا UE5، بلا GPU، بلا شاشة، بلا Git LFS — §2) **غير قادرة فيزيائيًا** على بناء أو تشغيل Unreal Engine، وبالتالي فإن أي ادعاء "مشروع يعمل" كان اختلاقًا صريحًا يُخالف قواعد المالك.

**ما أُنجز فعليًا** (كلٌّ منها منفَّذ ومتحقق منه آليًا في هذه الجلسة):

1. **هيكل مشروع UE 5.4 كامل الأجزاء النصية** (`03_Unreal/`): ملف `TLS.uproject`، قواعد البناء `Target.cs`، وحدة C++ كاملة (`TLS.Build.cs` + كلاسا `TLSGameMode` و`TLSCharacter`)، وملفات الإعدادات الثلاثة — جميعها ملفات قياسية يقرؤها المحرك كما هي، وتُبنى على محطة Windows بأمر واحد مُؤتمت.
2. **اختبار قابل للعب مصمَّم ومكوَّد بالكامل**: غرفة اختبار 20×20 م تُبنى ذاتيًا عند التشغيل (أرضية/جدران/عوائق تصادم/شمس Lumen)، وشخصية إدموند blockout بحركة **مشي/جري/انحناء — بلا قفز** (عقد M0) عبر **Enhanced Input** بلوحة مفاتيح وفأرة وذراع، مبنية كليًا في الكود دون الحاجة لأي ملف `.uasset`.
3. **تحقق حقيقي للأصول** أعلى من أي وقت مضى: إعادة استيراد ملفي FBX داخل Blender نظيف وقياسهما فعليًا — **16/16 فحصًا ناجحًا** بما فيها القياسات والمحاور والمحور الارتكازي وفتحات المواد (§4).
4. **أتمتة Windows كاملة**: ثلاثة ملفات `.bat` (بناء → استيراد+معايرة آلية → تشغيل اللعب) + سكربت بايثون يعمل داخل محرر UE يستورد الأصلين و**يقيس CAL-01 رقميًا** ويكتب تقرير JSON وينشئ مستوى `L_TLS_TestRoom`.
5. **CI حقيقي**: سير عمل GitHub Actions يشغّل فاحصي المشروع (68 فحصًا + 39 فحصًا) على كل push — نُفِّذ فعليًا مع هذا الدفع (§6).

**حالة الأصول في السجل لم تتغير: `EXPORTED`** — لن تُرفع إلى `IMPORTED` إلا بعد استيراد فعلي داخل UE على محطة Windows (IMP-01) — هذا التزام موثق ويفحصه الفاحص آليًا.

## 4) المهمة 3 — مشروع Unreal Engine (ما بُني فعليًا ولماذا على هذا الشكل)

**القرار الهندسي الموثق:** كل ما في UE مشروع نصي المنشأ (`.uproject` = JSON، `Config/*.ini`، `Source/*.cpp/.h/.cs`) يمكنتأليفه **دون تشغيل المحرك** — وهذه ليست محاكاة بل هي الملفات القياسية ذاتها التي يقرؤها UE. ما لا يمكن إنتاجه هنا هو الثنائيات (`.uasset`/`.umap`) وتجميع الكود — وكلاهما مؤجل بصدق إلى Windows.

### 4.2 تصميم الاختبار القابل للعب (المهمة 4 — مكوَّد بالكامل، تشغيله على Windows)

عقد M0 في `MILESTONE_PLAN` ينص على: غرفة اختبار `L_TLS_TestRoom`، شخصية blockout بـ Enhanced Input (KB+M + ذراع) **تمشي وتجري وتنحني — لا تقفز**. التنفيذ:

- **الغرفة تُبنى برمجيًا عند StartPlay** (لا تتطلب أي بناء يدوي في المحرر): أرضية 20×20 م سطحها عند Z=0 بالضبط، 4 جدران بارتفاع 3 م، 3 عوائق تصادم (مكعب 1 م / 0.5 م للانحناء خلفه / عمود 2 م)، شمس متحركة (Lumen مفعَّل في الإعدادات).
- **الشخصية**: كبسولة 35×175 سم (عقد 1.75 م)، شكل رمادي مؤقت من مكعب المحرك القياسي (الهيكل الحقيقي `TLS_Rig_Human` عمل M1)، ذراع كاميرا زنبركية 4 م مع تأخير سلس، تدور مع دوران الحركة.
- **التحكم (Enhanced Input، مبني بالكامل في الكود — بلا ملفات uasset)**: WASD/العصا اليسرى للحركة، الفأرة/العصا اليمنى للنظر، **Shift (مع الاستمرار) للجري**، **C للانحناء**، أزرار الذراع مكافئة. القفز معطَّل صراحة (`JumpZVelocity = 0`).
- **تعويض غياب PlayerStart في الخريطة الفارغة**: الـ GameMode يضمن وجود البيدق بـ `RestartPlayerAtTransform` — لا حالات "الكاميرا بلا شخصية".

### 4.3 فحوص CAL-01 داخل اللعبة (C++) وعبر المحرر (Python) — قيم عقدية

الثوابت المقارَنة مشتقة من العقد (`TECHNICAL_PIPELINE` §4/§9 + البيان الفعلي) ومن **القياس الفعلي أعلاه**، بتسامح **0.5%** (معيار قبول M0):

| الفحص | القيمة المتوقعة (سم) |
|---|---|
| gnomon: الحجم الكلي X/Y/Z | 135 / 100 / 77 |
| gnomon: نطاق X | من -50 إلى **+85** (امتداد السهم = إثبات الاتجاه +X) |
| gnomon: نطاق Y / Z-min | ±50 / 0 (المحور الارتكازي عند الأصل) |
| gnomon: فتحات المواد | **5** |
| figure: الارتفاع / باع الذراع / العمق | 175 / 57 / 25 |
| figure: Z-min | 0 (المحور عند القدمين) |

مسارا الاستيراد موحَّدان بين الطرفين (`/Game/TLS/ENV/TLS-ENV-00X/SM_TLS-ENV-00X` — اصطلاح التسمية §3) ويفحص توحيدهما آليًا (فحص المنصة رقم 6).

## 9) ما هو مطلوب من المالك على محطة Windows (دليل تنفيذ دقيق)

**المتطلبات مرة واحدة:**
1. Windows 10/11 64-bit بعتاد "الموصى به" (انظر `docs/PLATFORM_STRATEGY.md`).
2. **Unreal Engine 5.4+** عبر Epic Games Launcher (المسار القياسي `C:\Program Files\Epic Games\UE_5.4`).
3. **Visual Studio 2022** مع حملة "Game development with C++".

**التنفيذ (ثلاث خطوات مؤتمتة — من مجلد المستودع):**
```bat
cd 03_Unreal\Scripts
01_build_editor.bat            &rem 1) يجد المحرك ويبني الثنائيات (دقائق)
02_import_and_calibrate.bat    &rem 2) يستورد الأصلين + يقيس CAL-01 + ينشئ L_TLS_TestRoom + يكتب Reports\import_report.json
03_play_test.bat               &rem 3) يفتح المحرر على خريطة الاختبار — اضغط Play
```

**معايير نجاح M0 للتحقق بعدها (بوابة الانتقال إلى M1):**
- `import_report.json` فيه `"overall_pass": true` (تسامح ≤0.5%) — وتقرير `Reports\calibration_ingame.json` مثله من داخل PIE.
- سجل Output يظهر أسطر `[CAL-01] PASS` كاملة.
- الحركة سليمة: مشي/جري (Shift)/انحناء (C)، تصادم مع الجدران والعوائق، بلا قفز.
- لقطات F9 تُنسخ من `03_Unreal\Saved\Screenshots\` إلى `reports/` (دليل CAL-01 الموثق).
- عندها فقط: تُرفع حالة الأصلين إلى `IMPORTED` وتُقفل الإعدادات Preset وتُوقَّع وثيقة القفل — وتُفتح M1 رسميًا.
