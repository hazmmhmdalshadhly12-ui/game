# QUEST_ARCHITECTURE — بنية المهام والتحقيق والقرارات
> **v0.1 — 22 أكتوبر 2026** | مرجع القصة: `GAME_BIBLE.md` §4. مرجع الشخصيات: `CHARACTER_REGISTRY.md`. هذه الوثيقة تعرّف **الأنظمة** (كيف تُبنى المهام والأدلة والحوار والنهايات) و**المحتوى** (قائمة الفصول والمهام الجانبية).

## 1. النموذج المعطياتي (Data Model)
```
QuestDef {
  id: "Q-M-C1" | "Q-S01".."Q-S12"          # رئيسية/جانبية
  title, giver, chapter, day_window         # نافذة الأيام
  objectives: [ ObjectiveDef ]
  flags_set: { FLG_*: value }               # أعلام تُرفع عند الإتمام
  rewards: info | access | trust | item     # لا نقاط خبرة — مكافآت ملموسة
}
ObjectiveDef {
  id, description, hint_tier (0..2)         # تلميحات متدرجة اختيارية
  tasks: [ TaskDef ]                        # شروط إنجاح قابلة للقياس
  optional: bool                            # الأهداف الاختيارية لا تسد الطريق
}
TaskDef { type: reach | observe | collect | inspect | dialogue | restore | decide | timed }
```
- **ال journal (دفتر إدموند):** عرض نصي بتقسيم ثلاثي (الفصول/الجانبية/الخيوط المفتوحة) — يُحدَّث بأسلوب مذكرات نقّاش (نص من العربة الأولى).
- **التلميح:** ثلاث درجات (صامت ← إشارة ← توجيه صريح) تبقى اختيارية بالكامل (إعدادات الوصول).

## 2. منظومة الأدلة والاستنتاج (Evidence & Deduction)
### 2.1 أنواع الأدلة (التصنيف القضائي — عمود فقري للنهايات)
| النوع | مثال | قيمة قضائية | ملاحظة |
|---|---|---|---|
| مادي (Physical) | مفتاح Y Porth، زجاجة الأفيون، خدوش الباب | عالية | يُجمع من العالم ويُفحص على المائدة |
| شهادي (Testimonial) | إفادة كولز عن "الظل" | متوسطة | قيمتها تتبع ثقة الشاهد وموثوقيته |
| وثائقي (Documentary) | صفحة سجل، ورقة الغينيا، شهادات بيلامي | عالية | السجل نفسه يظل "فرضية" حتى تدعّمه أدلة |
| سماعي (Hearsay) | إشاعة متحولة | ضعيفة/ملغومة | قد تكون مفيدة استقصائيًا وتسقط قانونيًا |
كل دليل يحمل: `source, day_acquired, reliability (0..1), chain_of_custody` — **النهاية القضائية E1 تتطلب ملفًا بغالبية أدلة موثوقية ≥0.7 وسلسلة حفظ سليمة** (يُشرح للاعب دراميًا عبر بريتشارد: "قصتك جيدة يا سيد ڤيل؛ دعك من قصص الأساطير").
### 2.2 لوحة السجل (Deduction Board)
- العقد: أدلة/شهادات/أشخاص (تظهر ببطء — بلا إغراق).
- الروابط يرسمها اللاعب؛ الروابط المنطقية الخاطئة تُعلَّم "تناقض" بتعلة نصية (مثال: ربط ظل البرج بـ"الجوع" يُعلم: "لا يوجد ما يثبت وجوده أصلًا").
- الاستنتاج المؤهل (Insight) يتطلب غالبًا اتحاد مصدرين مختلفي النوع (§6.1 من الإنجيل) — الاستثناءات موثقة في الجدول أدناه لكل فصل.
- **قاعدة تصميمية:** لا يوجد استنتاج واحد إجباري للحل النهائي؛ 3 مسارات أدلة بديلة على الأقل لكل حقيقة كبرى (مثال حقيقة "من أغلق الباب": مسار المفتاح المادي / مسار شهادة بروسير / مسار أوراق شان).

## 5. منظومة الحوار (Dialogue System)
- **العقد:** حوار شجري (node graph) داخل محرر داخلي (M2: أداة تأليف داخل UE بناء على DataTable+Graph بسيط)؛ الملفات المصدر في `05_Narrative/dialogues/*.json` بصيغة موثقة (nodes/conditions/choices/consequences).
- **شروط العقد (Conditions):** أعلام، ثقة ≥ عتبة، دليل بحوزة، مستوى ويلزية، وقت اليوم، حالة الطقس، حالة شخصية (موقوف/ميت/خائف).
- **النبرات:** كل خيار لاعب يُوسم (رقيق/رسمي/ضاغط/صامت)؛ للنبرات أوزان ثقة لكل شخصية (القس يستجيب للرسمي؛ نان للرقيق؛ غريفيثس لا يستجيب إلا للضاغط خوفًا).
- **تقديم الدليل:** بطاقة دليل تُعرض داخل الحوار؛ ردود الشخصيات موزعة: (يقبل/ينكر=تناقض يُسجل/ينكسر=سطر اعتراف).
- **الويلزية:** النص الويلزي يُعرض مكتوبًا دائمًا؛ الترجمة تظهر تلقائيًا عند FLG_EDMUND_WELSH_LEVEL الكافئ وإلا تُعرض الكلمات الغريبة مموهة (+ اقتراح "الدرس").
- **قواعد كتابية إلزامية:** صوت إدموند واحد ثابت (ساخر مكتوم)؛ لا معلومات مفسّرة مجانية (exposition) — كل معلومة تحمل ثمنًا اجتماعيًا؛ ممنوع الخيار "الطيب/الشرير" المصنّع — كل خيار مبرر دراميًا.

## 8. الحفظ ونقاط التحقق (Save System)
- حفظ يدوي في أي وقت من **منضدة الأب** (D1) فقط — قرار تصميمي: "المكتب = الذاكرة".
- نقاط تحقق تلقائية عند دخول/خروج المناطق وبعد كل حدث فصلي.
- بنية الحفظ: JSON تسلسلي شامل (أعلام، أدلة+سلاسل الحفظ، ثقة/سمعة، جداول NPC اللحظية، إشاعات نشطة) — يخضع لاختبار ذهاب-إياب في M2 (`NPC_SIMULATION.md` §الاختبار).

## 9. معايير القبول والتوثيق
1. كل فصل يقبل فقط إذا: (أ) أهدافه قابلة للقياس في اللعب، (ب) له 3 مسارات أدلة على الأقل لحقيقته الكبرى، (ج) لا يعتمد على دليل من مهمة اختيارية **إلا** وله بديل إجباري.
2. أي مهمة تُضاف/تُحذف تُحدَّث هنا ثم في `ASSET_REGISTRY.csv` (أصولها) ثم في محرك الجداول (`NPC_SIMULATION.md`).
3. اختبار "القراءة الصامتة": كل فصل يُتلى كنص قبل التنفيذ — إن لم يُشرح منطق الحل شفويًا للمستمع، يُعاد التأليف (قاعدة منع "غموض الكاتب").
