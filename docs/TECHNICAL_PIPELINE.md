## 3. اصطلاحات التسمية (Naming Convention)
- **معرف الأصل (AssetID):** `TLS-<CAT>-<NNN>` حيث CAT من حرفين إلى ثلاثة ∈ {ENV, CHR, PRP, ANM, MAT, TEX, SND, UI, VFX, SKL}. مثال: `TLS-ENV-001` و`TLS-UI-001`.
- **ملف Blender:** `tls_<cat>_<nnn>_<snake_name>.blend` — مثال محقق: `tls_env_001_calibration_gnomon.blend`.
- **ملف التصدير:** نفس الاسم + `_v###.fbx` — مثال محقق: `tls_env_001_calibration_gnomon_v001.fbx`.
- **داخل UE:** بادئات معيارية: `SM_` static mesh، `SK_` skeletal، `S_` skeleton، `A_` anim، `M_` material، `MI_` instance، `T_` texture، `LS_` level snapshot، `L_` level، `BP_` blueprint، `WBP_` widget، `SB_` soundbank… مع مسار `/Game/TLS/<Category>/<Asset>/`.
- **القوام (لاحقات):** `_BaseColor` (sRGB)، `_Normal` (linear)، `_ORM` (linear؛ R=AO، G=Roughness، B=Metallic)، `_Emissive` عند الحاجة، `_Opacity` نادرًا.
- **إصدارات:** داخل الملف نفسه برفع `_v###` عند كل تصدير يلي تغييرًا جوهريًا؛ الحالة توثق في `ASSET_REGISTRY.csv` فورًا (لا إصدارات متشعبة — مسار واحد).

## 4. المقاييس والاتجاهات والمحاور (The Axis & Scale Contract)
| البند | المعيار | التحقق |
|---|---|---|
| وحدات Blender | Metric، Unit Scale = 1.0 | افتراضي المصنع |
| التحويل | **1 م = 100 uu** | عبر `FBX_SCALE_UNITS` (أُنتج به فعليًا) |
| اتجاه التأليف | الشخصيات والأصول تواجه **-Y في Blender** | فُحص بالسهم الأحمر في gnomon |
| الاتجاه عند الاستيراد | تواجه **+X في UE** (forward) | عقد يُتحقق منه بـ CAL-01 عند M0 |
| المحور الارتكاز (Pivot) | مركز قاعدة الأصل عند نقطة الأصل (0,0,0) — الأقدام للشخصيات، الأرض للمباني | محقق في الأصلين الفعليين |
| التحويلات | `Ctrl+A → All Transforms` مطبقة قبل التصدير للأصول الثابتة | محقق (سكربت `transform_apply`) |

**إعدادات تصدير FBX المعيارية (مُتحقق إنتاجها فعليًا في Blender 5.0.1):**
```
use_selection        = True
object_types         = {'MESH'}          (Skeletal: {'ARMATURE','MESH'})
axis_forward         = '-Y'
axis_up              = 'Z'
apply_scale_options  = 'FBX_SCALE_UNITS' ← يحقق 1 م = 100 uu
global_scale         = 1.0
mesh_smooth_type     = 'OFF'             (النورمالات تُخبز كما هي)
bake_space_transform = False             (لا خبز تحويل الفضاء للهياكل)
add_leaf_bones       = False             (سلوك الهياكل)
```
> **نتيجة فعلية موثقة:** المخرجات FBX ثنائية **v7400** (FBX 7.4) — مدعومة كاملة من مستورد UE. لو أظهر مستورد UE انحراف 90° عند CAL-01 فالإجراء الموثق هو: تصحيح "إعدادات المحطة" لا "تدوير يدوي للأصل" (تدوين السبب في السجل وإعادة التحقق بالكامل).

## 5. معايير الشبكة (Mesh Standards)
1. **الطوبولوجيا:** Quads نظيفة؛ تجنب Poles على منحنيات الوجه؛ كثافة الحواف تتبع الانحناء (خصوصًا وجوه T1).
2. **ميزانية المثلثات (LOD0):** شخصية T1: ≤45k؛ T2: ≤32k؛ رؤوس Crowd: ≤8k؛ Prop بطل: ≤10k؛ قطعة Kit: ≤8k. المباني الفريدة: **Nanite** بلا سقف صارم مع انضباط هندسي.
3. **سياسة Nanite:** كل ENV الفريدة وKit → Nanite **مفعل**؛ الشخصيات → **تقليدي** بسلسلة LODs (4 مستويات، تباعد الشاشة 100%/40%/20%/10%)؛ Props البطلة حسب الفحص.
4. **LOD يدوي أو تلقائي:** ENV التقليدي → `_LOD1..` يدوي عند الحاجة؛ CHR → تقليص في Blender + تصدير ملف واحد بمستويات مسماة.
5. **UV:** قناة UV0 non-overlapping للأصول النهائية (trimsheets تسمح overlap مقصود بتصريح في السجل)؛ UV1 فريدة للـ lightmap في UE (إن لزم للمشاهد التقليدية).
6. **الحدود:** لا وجوه داخلية عديمة الفائدة؛ Normals منسابة (smooth) مع hard edges عند حواف المواد.

## 6. التصادمات (Collision)
- **ثابت (ENV/PRP):** صناديق/محدبات مبسطة مسبوقة `UCX_` داخل ملف Blender نفسه؛ أو "Complex as Simple" للـ Nanite بعد موافقة الأداء.
- **شخصيات:** كبسولة UE الافتراضية + إعداد مخصص للدوران في الأبواب المنخفضة (ارتفاع إدموند 1.78 م والباب 1.85 م — لحظة "الانحناء" مقصودة سلوكيًا).
- **أبواب/تفاعلات:** محدب بسيط + علامة تفاعل (Tag) — لا فيزياء أجسام رخوة في M1.

## 7. الخامات والقوام (Materials & Textures)
1. **النموذج:** PBR metal/rough (توافق UE) — لا specular/gloss.
2. **الحزم:** BaseColor منفصل + **ORM مدمج** (R=AO، G=Roughness، B=Metallic) + Normal (OpenGL Y+ من Blender → يُفعل "Flip Green Channel" في إعدادات النسيج بـ UE).
3. **sRGB:** `_BaseColor` فقط sRGB؛ Normal/ORM خطية دائمًا.
4. **كثافة القوام (texel density):** وجوه T1: 1024px/م؛ أجسام T1: 512px/م؛ Props بطلة: 512px/م؛ Kit ENV: 256px/م + trimsheet 2048 للمقاطع الطويلة (عارضات الجدران/الأدراج).
5. **الحد الأقصى للنسيج الواحد:** 2048 (4096 استثناء موثق بموافقة الأداء).
6. **الأصل:** كل قوام مُخبز أو مرسوم داخليًا؛ ممنوع أي texture من مصادر غير موثقة؛ فحص "بوابة الأصالة" قبل APPROVED.
7. **Material Instances أولًا:** الألوان/الشدات تختلف عبر MI_ بلا إعادة خبز (أزياء Crowd نموذجًا).

## 8. الهياكل العظمية والأنيميشن (Skeletal & Animation)
- **الهيكل الأصلي `TLS_Rig_Human v1` (TLS-SKL-001):** يبدأ من شخصية مرجعية 1.75 م (متوفرة فعليًا TLS-ENV-002)؛ هيكل هرمي: root → pelvis → spine×3 → neck/head + أطراف بعظام لف (twist) للأ ساعدين والساقين؛ ≈65–75 عظمة؛ تسمية `TLS_B_<part>L/R`؛ لا عظام mesh غير ضرورية.
- **وضعية Bind:** A-pose بميل 15° (أوضع طبيعيًا لملابس 1847 من الأكتاف المائلة).
- **الأنيميشن:** مصدر 30fps؛ أفعال Action مستقلة بالتسمية `tls_anm_<nnn>_<name>`؛ Root Motion لأفعال الحركة فقط؛ التصدير FBX بالهيكل + الميش مرة أولى (Skeleton asset) ثم الأفعال منفصلة `object_types={'ARMATURE'}` مع "Only Selected".
- **Retargeting:** داخلي بين إصدارات الهيكل عبر UE IK Retargeter — لا اعتماد على هيكل خارجي (سياسة أصالة §GAME_BIBLE 11).

- **مصفوفة اختبارات الاستيراد (تُنفذ في M0 قبل أي إنتاج):**
  | الاختبار | الأصل | معيار النجاح |
  |---|---|---|
  | IMP-01 (Static) | TLS-ENV-001 gnomon | حجم 100×100×20 سم للقاعدة بالضبط؛ السهم الأحمر يواجه +X؛ المحور الارتكاز عند الأصل؛ 5 مواد وصلت كـ slots (Base/Body/AxisX/AxisY/AxisZ — مطابق البيان الفعلي) |
  | IMP-02 (Skeletal) | TLS-SKL-001 + CHR-001 blockout | المقياس 1.75 م؛ الجلد سليم بلا تشوه؛ الهيكل بعظام 65+؛ Bind بلا negative scale |
  | IMP-03 (Anim) | TLS-ANM-001..003 | معدل الإطاعات صحيح؛ Root Motion مقروء؛ بلا إزاحة hip |

## 10. بوابات الجودة لكل أصل (Asset QG Gates)
حالة كل أصل في `ASSET_REGISTRY.csv` تسير في هذه السلسلة، ولكل بوابة قائمة فحص في السكربت `tools/validate_project.py` أو مراجعة بشرية موثقة:
`PLANNED → BLOCKOUT → MODELED → TEXTURED → (RIGGED/ANIMATED) → EXPORTED → IMPORTED → INTEGRATED → APPROVED`
- **BLOCKOUT:** الأبعاد والمحاور مطابقة لجدول §4؛ محور ارتكاز صحيح.
- **TEXTURED:** قوائم القوام مكتملة باللاحقات؛ كثافة القوام ضمن الجدول §7.
- **EXPORTED:** FBX موجود في `exports/` بالإعدادات المعيارية (الأصلان TLS-ENV-001/002 وصلا فعليًا هذه الحالة).
- **IMPORTED:** نجاح مصفوفة IMP المناسبة + لقطة/سجل استيراد.
- **APPROVED:** فحص بصري (إضاءة الاختبار `L_TLS_TestRoom`) + بوابة الأصالة + تحديث السجل.

## 11. سير العمل والنسخ (Versioning)
1. **Git flow مبسط:** `main` محمي؛ فروع `feat/<assetid>-<desc>`؛ الدمج بمراجعة واحدة على الأقل.
2. **LFS locks** على ملفات `.blend` قيد التحرير (منع تعارضات ثنائية).
3. **التحقق الآلي المستمر:** عند كل push يُشغل `tools/validate_project.py` (فحص السجل + الاتساق) — يعمل الآن ضمن هذه البيئة وجاهز لربطه بـ GitHub Actions في M0.
4. **نسخ الأدلة:** `.blend` يخزن stages غير مضغوطة؟ لا — يخزن مضغوطًا (.blend1 معطل: `save_version=0` — مطبق فعليًا في السكربت).
